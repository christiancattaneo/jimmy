Database layer auditing

A crowbar tests the front door. jimmy tests the basement.

jimmy pries open the database your application thinks is locked. It pokes at the gaps the other tools miss: row-level security, multi-tenant isolation, transaction anomalies, schema integrity, and migration safety. Inspired by Jepsen and Elle, pointed one layer up at your app's use of the database.

The gap nobody else covers

Static scanners read your code. Pen-testers attack the query string. Load tools push until it breaks. None of them reason about who is allowed to see which rows under which session, or whether the data is correct after concurrent writes.

RLS

RLS bypass

Tables with RLS disabled, permissive USING (true) policies, write policies missing WITH CHECK, roles with BYPASSRLS, and tenant columns the policy forgets to filter on.

FUZZ

Multi-tenant isolation

Seeds two synthetic tenants, authenticates as A, and mechanically proves A cannot SELECT, UPDATE, DELETE, or INSERT against B across every table, role, and operation.

RPC

SECURITY DEFINER audit

The biggest RLS bypass in Supabase. Flags definer functions callable by anon or authenticated (they run as the owner) and those without a pinned search_path.

TXN

Transaction anomalies

Hermitage-style probes for lost update, read skew, write skew, G2, and phantoms at every isolation level, plus a FOR UPDATE control that proves the fix works.

DDL

Migration safety

Squawk-style linter: NOT NULL without default, non-CONCURRENTLY indexes, type rewrites, FK/CHECK without NOT VALID, DISABLE RLS, and missing lock_timeout.

SQL

Schema integrity

Missing foreign keys, foreign-key columns with no index, nullable columns the app assumes are required, tables with no primary key, and tenant-spanning cascade deletes.

Deterministic verdict, generative inputs

The thing being checked is always a pure function of a recorded history, so a result is reproducible and trustworthy. Generation lives on the input side: enumerate the matrix, fuzz the schedule, synthesize adversarial data.

01

Introspect

Read pg_catalog and information_schema into a deterministic snapshot: tables, columns, constraints, policies, roles, indexes, functions.

02

Enumerate

Generate the finite (table x role x operation) matrix from the schema itself. No guessing, no AI deciding pass/fail.

03

Probe

Seed throwaway tenants inside a rolled-back transaction, impersonate each role, and record every attempt and its outcome.

04

Check

Any case where A touched B's data is a finding. The verdict is mechanical. Reports come out as markdown, JSON, and SARIF.

Install

Read-only by default. Refuses to run on a database whose name looks like production. Statement and lock timeouts on every connection.

Run without installing

$ npx jimmy-db migrations lint --dir ./supabase/migrations
$ npx jimmy-db rls audit --db $DATABASE_URL

Adopt on an existing database

# accept today's findings, fail only on new ones
$ jimmy scan --db $DATABASE_URL --update-baseline
$ jimmy scan --db $DATABASE_URL --baseline .jimmy-baseline.json

In CI for migration PRs

- uses: christiancattaneo/jimmy@main
  with:
    command: migrations
    fail-on: high
